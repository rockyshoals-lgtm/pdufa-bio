# 🟡 Event schema — I overstated this last audit. Correcting.

Last time I flagged "94% invalid, likely because VirtualLocation is wrong for a physical FDA decision." **On inspection of the actual markup, that reasoning was wrong.** The Event is internally consistent:
```json
{"@type":"Event","startDate":"2026-07-26","endDate":"2026-07-26",
 "eventStatus":".../EventScheduled",
 "eventAttendanceMode":".../OnlineEventAttendanceMode",
 "location":{"@type":"VirtualLocation","url":".../pdufa/MNKD"},
 "organizer":{"@type":"Organization","name":"U.S. Food and Drug Administration"}, ...}
```
`VirtualLocation` **paired with** `OnlineEventAttendanceMode` is coherent — it's not the physical/virtual mismatch I claimed. eventStatus, organizer, name, description, image, url are all present. This schema is far more complete than "94% invalid" implies.

**The one real remaining gap:** `startDate` is date-only (`2026-07-26`) with no time or timezone. Google's Event guidelines want `2026-07-26T00:00:00-04:00`-style ISO with offset for full eligibility; date-only tends to degrade eligibility in aggregate. Likely fix = add a nominal time + TZ. Also, GSC's "94%" figure lags crawl — it may reflect the pre-fix state and improve on its own. **Action: run the URL through the Rich Results Test, add time+TZ to startDate if it flags, then let GSC recrawl.** Lower priority than I made it sound.
