# 🔴 P0 — The API contradicts itself on MannKind, and omits the outcome entirely

MannKind's **FUROSCIX ReadyFlow was FDA-approved July 24, 2026** — verified against MannKind's own release, HCPLive, and RTTNews. **The rendered site gets this exactly right:** `/decisions` and the homepage both show **"MNKD · 2026-07-24 · ✓ Approved."**

**The API does not.** Full record from `/api/v1/events?ticker=MNKD`:
```json
{ "status": "Decided",
  "date": "2026-07-26",          ← scheduled PDUFA date, NOT the 7/24 decision date
  "days_to_decision": 1,          ← claims the decision is 1 day in the FUTURE
  "updated_at": "2026-07-24T11:02:32Z",
  /* no "outcome" field anywhere */ }
```

Three defects in one record:

1. **No `outcome` field.** The API says `Decided` but never says **Approved**. The site clearly *has* the outcome — it renders "✓ Approved" — so the backend knows; the API serializer just doesn't expose it. A consumer of the API cannot tell an approval from a CRL. **This is the single most valuable field the API is missing**, and it's the whole point of a "what actually happened" archive.

2. **`date` still shows the scheduled 7/26, not the actual 7/24 decision.** Combined with #3, the record reads as a future event that has somehow already been decided.

3. **`days_to_decision: 1` on a `Decided` event.** Internally contradictory — Decided and "+1 day to go" cannot both be true. This is a computed field that wasn't recomputed when status flipped.

**Why this is P0, not cosmetic:** `/llms.txt` is live and explicitly invites ChatGPT/Perplexity/Gemini to read this API. An LLM ingesting this record sees *"MannKind FUROSCIX, PDUFA July 26, decided, 1 day to decision, outcome unknown"* — a future-dated, outcome-less, self-contradicting record for a drug that was **approved two days ago**. The rendered page is right; the machine-readable surface is wrong. Same class of defect as the readout-precision split I flagged on 07-19 — **the page and the API have diverged again.**

### The fix is contained (the data exists)
On decision capture, the pipeline flips `status → Decided` but doesn't finish the job. Add to the serializer/updater:
- expose **`outcome`** (`Approved` / `CRL` / `Withdrawn`) — already in the backend, just surface it;
- set **`decision_date`** to the actual date (7/24), keep `date` as the PDUFA target or clearly label which is which;
- recompute **`days_to_decision`** — must be ≤ 0 (or null) once Decided.

```python
# tests/test_decided_consistency.py
for r in api_events:
    if r['status']=='Decided':
        assert r.get('outcome') in ('Approved','CRL','Withdrawn'), f'{r["ticker"]}: Decided w/o outcome'
        assert (r.get('days_to_decision') or 0) <= 0, f'{r["ticker"]}: Decided but days_to_decision>0'
```
