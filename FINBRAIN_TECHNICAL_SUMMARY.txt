================================================================================
FEATURE ENGINEERING SPECIFICATION
================================================================================

FEATURE SET 1: NEWS SENTIMENT (3 features)
  Target API: mcp__finbrain__news_sentiment_by_ticker
  Lookback: T-30 to T-1 (30 days pre-readout)
  Computation:
    - finbrain_sentiment_avg_30d = mean(sentiment[T-30:T-1])
    - finbrain_sentiment_avg_7d = mean(sentiment[T-7:T-1])
    - finbrain_sentiment_trend = sentiment_7d - sentiment_30d

FEATURE SET 2: ANALYST RATINGS (3 features)
  Target API: mcp__finbrain__analyst_ratings_by_ticker
  Lookback: 90 days pre-readout
  Computation:
    - finbrain_analyst_upgrades_90d = count(rating_changes == 'upgrade')
    - finbrain_analyst_downgrades_90d = count(rating_changes == 'downgrade')
    - finbrain_analyst_net_signal = upgrades - downgrades

FEATURE SET 3: INSIDER TRANSACTIONS (2 features)
  Target API: mcp__finbrain__insider_transactions_by_ticker
  Lookback: 90 days pre-readout
  Computation:
    - finbrain_insider_net_90d = count(buys) - count(sells)
    - finbrain_insider_value_90d = sum(buy_values) - sum(sell_values)

FEATURE SET 4: OPTIONS PUT/CALL RATIO (3 features)
  Target API: mcp__finbrain__options_put_call
  Lookback: T-30 to T-1 (30 days pre-readout)
  Computation:
    - finbrain_pcr_avg_30d = mean(put_call_ratio[T-30:T-1])
    - finbrain_pcr_avg_7d = mean(put_call_ratio[T-7:T-1])
    - finbrain_pcr_trend = pcr_7d - pcr_30d

TOTAL: 11 NEW FEATURES
  - All T-1 compliant (knowable before readout)
  - All aggregated as rolling averages or counts
  - All designed to capture pre-event market positioning

IMPLEMENTATION DETAILS
================================================================================

DATA FLOW:
  gungnir_readout_analysis.csv (1,752 events)
  ↓
  finbrain_feature_extractor.py (Python script)
  ├─ Cache FinBrain API calls (per ticker, per metric)
  ├─ Compute features for each event
  ├─ Handle missing data via phase-average imputation
  └─ Save to finbrain_features.json
  ↓
  finbrain_features.json (keyed by "ticker|date")

CACHING STRATEGY:
  - Per-ticker API calls (avoid redundant data fetches)
  - Data cached in memory during script run
  - If re-running needed, would implement persistent cache
  - FinBrain API likely has rate limits (not specified)

MISSING DATA HANDLING:
  - Approach: Phase-average imputation (same as CT.gov in v33)
  - For each phase (1, 2, 2/3, 3, etc.), compute mean of non-null values
  - Fill missing feature values with phase-appropriate mean
  - Expected coverage: ~70-80% (major pharma well-covered by FinBrain)
