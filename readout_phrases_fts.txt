# readout_phrases_fts.txt — for:  edgar_miner.py fts
#
# EXACT PHRASES ONLY. `fts` is server-side EDGAR full-text search and rejects `re:` lines.
# For regex use readout_phrases_scan.txt with the `scan` subcommand.
#
# THE ADJACENCY RULE — the single thing that governs this file.
# EDGAR FTS matches a quoted phrase only if the words are ADJACENT. Intervening words break it:
#     "to report topline"  does NOT match  "to Report 36-Week Topline Results"
# So every line here is a SHORT, UNIVERSAL fragment. Long natural-sounding phrases feel more
# precise and silently match almost nothing. Let the fragment find the DOCUMENT; let the regex
# in readout_phrases_scan.txt (or the miner's LEAD/PR_SCHED patterns) find the DATE inside it.
#
# Keep this list SHORT and HIGH-YIELD. Every phrase is a full paginated crawl. Cheap phrases
# that return the same documents as another phrase cost real time and add nothing — the `scan`
# cache dedupes by document, so overlap is wasted requests, not wasted rows.
#
# WHAT SEC FILINGS CAN AND CANNOT GIVE YOU (measured, 2026-07-16, n=158 sec_edgar rows):
#   quarter/half precision : 158  ("topline expected in Q3 2026")
#   EXACT DAY              : 0
# Zero. Not a tuning problem — a scheduling PR ("we will report on July 13") is usually not
# material enough to furnish as an 8-K exhibit, so it never enters EDGAR at all. It goes over
# the newswire. Do not add more phrases hoping for a day; use the FMP newswire leg for that.
# What SEC IS for: the company's own COMMITTED WINDOW, which CT.gov's estimate cannot give you.
