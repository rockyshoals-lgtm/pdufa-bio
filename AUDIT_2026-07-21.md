# 🔴 THE FINDING — the site claims "~5×/day refresh." The data is a single 10-day-old batch.

This is the one that matters, because it attacks the exact positioning you want to own.

**`/coverage` states, in writing:**
> *"Update cadence: The dataset refreshes on a schedule (**~5×/day via cron**) plus a full primary-source crawl."*
> *"Regenerated automatically on every data refresh."*

The homepage says **"Live"** three times.

**Every single one of the 384 API rows carries the same timestamp:**
```

```

`as_of` reports **2026-07-21** (today) — so the envelope says "today" while the contents haven't moved since July 11. **The freshness signal is cosmetic.** Nothing has been re-fetched in 10 days: not prices, not market caps, not new PDUFA announcements. The "~5×/day" claim is **falsifiable in one API call** — anyone who diffs `updated_at` against that sentence catches it, and it's the first thing a competitor doing a teardown (the way I do theirs) would run.

### It has already caused a concrete miss

Verified via primary reporting; verified absent from the API (0 hits on `centanafadine`, `otsuka`, `adhd`). A snapshot frozen on July 11 cannot carry a catalyst that needed a later refresh to land. The Enhertu July 7 breast-cancer decision is also absent (large-cap, may be out of scope — but it's a real July decision).

### Why this is the priority
You are not going to beat BioPharmaCatalyst on brand this quarter. The one claim you can win outright is **"the most current."** That claim is only true if the pipe actually runs. Right now the site *asserts* currency it isn't *delivering* — which is strictly worse than saying nothing, because it's a checkable overstatement on your core promise.

**Fix, in order:**
1. **Find out why the cron stopped.** 10 days flat = the refresh job is dead, silently. This is the waitlist-KV failure pattern again: a background job failing without alerting.
2. **Add a liveness guard the site can't lie past:** if `max(updated_at)` is older than ~48h, the homepage "Live" badge flips to "Last updated Jul 11" automatically, and `/coverage` reads the real cadence from the data instead of a hardcoded sentence. **The badge should be a function of the data, never a string.**
3. **Alert on staleness** — a daily check that pages you if the newest `updated_at` is > 24h old.
4. Then backfill: centanafadine 7/24 and any other post-July-11 confirmations.

```python
# tests/test_data_freshness.py — fail the build / page an alert
import json, urllib.request, datetime, sys
d = json.load(urllib.request.urlopen('https://www.pdufa.bio/api/v1/events?limit=2000'))
newest = max(r['updated_at'] for r in d['data'])
age_h = (datetime.datetime.utcnow() - datetime.datetime.fromisoformat(newest.replace('Z',''))).total_seconds()/3600
if age_h > 48:
    print(f'FATAL: newest updated_at is {age_h:.0f}h old ({newest}). '
          f'"Live"/"~5x/day" claims are false. Cron is likely dead.'); sys.exit(1)
```
